# Техническое задание: конвертер HTML/HTM → Markdown / PDF / DOCX

## 1. Назначение системы

Создать локальный инструмент `html2doc` для пакетной и одиночной конвертации HTML/HTM-файлов в форматы Markdown, PDF и DOCX. Система должна сохранять таблицы и изображения, корректно обрабатывать кириллицу и специфические артефакты OCR HTML, а также предоставлять три равноправных интерфейса: CLI, десктопное Qt6-приложение и веб-интерфейс с загрузкой ZIP-архива.

Источники размещены в каталоге `./лекции`. Результаты конвертации сохраняются в `./output/<имя_исходного_файла>/`.

## 2. Анализ исходных данных

### 2.1. Состав

- 13 HTML-файлов: `лекция-1.htm` … `лекция-10.htm`, `глоссарий.htm`, `чек-листы.htm`, `шаблоны.htm`.
- 10 каталогов `*<_files>` с 58 растровыми изображениями JPEG.
- Размеры изображений: примерно 835–973 × 483–590 px, 150 dpi.
- Общий объём изображений: около 2,3 МБ.

### 2.2. Особенности HTML

1. HTML 4.0 Transitional, не XHTML; обязателен tolerant HTML-парсер.
2. Кодировка UTF-8 с BOM, переводы строк CRLF.
3. `<title>` содержит `Отсканированное изображение` либо отсутствует — имя документа берётся из имени файла.
4. Отсутствуют `<thead>`, `<th>`, `<caption>`, `<main>`, `<section>`, `<figure>`, `<ol>`, `<pre>`, `<code>`, гиперссылки.
5. Заголовки:
   - несколько `<h1>` на файл;
   - `<h2>` встречаются внутри `<li>`;
   - один `<h2>` может содержать два раздела, разделённые `<br><br>`;
   - внутри заголовков есть пустые `<a name="bookmarkN">`.
6. Абзацы состоят из `<span class="fontN">`; один абзац может быть разорван на несколько span.
7. Жирный, курсив и подчёркивание задаются только inline CSS-стилями span.
8. Списки используют `style="list-style:none;"`, маркеры и номера вшиты в текст.
9. Таблицы используют `border="1"`, но не имеют семантической шапки; первая строка выделена жирным. В `шаблоны.htm` встречаются `colspan` и рваные строки.
10. Изображения имеют пустой `alt`, находятся в `<div>` или голым тегом; подписи расположены до, после или внутри контейнера. Часть подписей дублируется или не имеет изображения.
11. Встречаются `&nbsp;`, `&gt;`, `&quot;`, `<br clear="all">`.
12. CSS-классы `fontN` различаются между файлами; нельзя жёстко сопоставлять класс с уровнем заголовка.
13. MathML, SVG, base64, внешние стили и скрипты отсутствуют.

### 2.3. Выводы

Конвертер не может быть простой обёрткой над markdownify или Pandoc. Необходима промежуточная модель документа и слой нормализации, который отделяет семантическую структуру от физической вёрстки HTML.

## 4. Архитектура

### 4.1. Слои

```text
CLI / Qt6 GUI / Web API
          ↓
      pipeline.py
          ↓
reader.py → normalize.py → models.py → render/*
          ↓
      report.py / assets.py
```

### 4.2. Модули

- `models.py` — типы промежуточного представления.
- `reader.py` — чтение и разбор HTML.
- `normalize.py` — преобразование DOM в промежуточную модель.
- `assets.py` — разрешение и копирование изображений.
- `report.py` — сбор и сериализация предупреждений.
- `pipeline.py` — публичный API конвертации.
- `render/markdown.py`, `render/docx.py`, `render/pdf_html.py`, `render/pdf.py`.
- `cli.py`, `gui/*`, `web/*`.

### 4.3. Промежуточная модель

```python
@dataclass
class InlineRun:
    text: str
    bold: bool = False
    italic: bool = False
    underline: bool = False

@dataclass
class Paragraph:
    runs: list[InlineRun]

@dataclass
class Heading:
    level: int
    runs: list[InlineRun]

@dataclass
class ListItem:
    blocks: list[Block]
    marker: str | None

@dataclass
class ListBlock:
    ordered: bool
    items: list[ListItem]

@dataclass
class Table:
    rows: list[list[list[InlineRun]]]
    header_rows: int
    html_fallback: str | None = None

@dataclass
class Image:
    src: Path
    asset_path: Path
    width_pt: float | None
    height_pt: float | None
    alt: str
    caption: str | None

@dataclass
class Document:
    title: str
    source: Path
    blocks: list[Block]
    warnings: list[Warning]
```

Поддержка рекурсивных типов секций реализуется через `Block = Heading | Paragraph | ListBlock | Table | Image | Caption`. Вложенные списки моделируются через `ListItem.blocks`.

## 5. Pipeline конвертации

1. **Discovery** — найти файлы `.htm`/`.html`, проверить существование, определить output directory.
2. **Read** — прочитать файл как `utf-8-sig`, разобрать BeautifulSoup с fallback-парсером.
3. **Clean** — удалить `script`, `style`, пустые якоря, layout-теги `<br clear="all">`, нормализовать пробелы и entity.
4. **Normalize** — построить intermediate representation:
   - headings, paragraphs, lists, tables, images, captions (заголовки, абзацы, списки, таблицы, изображения, подписи);
    - inline-стили преобразуются в runs;

   - записать предупреждения.
5. **Assets** — разрешить относительные пути изображений относительно каталога исходника, скопировать в `assets/`.
6. **Render** — вызвать выбранные рендеры.
7. **Report** — записать `conversion-report.json`.

## 6. Правила нормализации

### 6.1. Заголовки

- `<h1>` считается началом логического раздела.
   - `<h2>` внутри единственного `<li>` поднимается на уровень выше списка.

- `<br><br>` внутри `<h2>` разделяет заголовок на два последовательных заголовка.
- Ручная нумерация (`1.`, `1.1.`) считается частью заголовка и сохраняется.
- Пустые `<a name>` удаляются без создания ссылок.

### 6.2. Списки

- Для `list-style:none` не генерируется автоматический маркер Markdown, если текст уже начинается с `•`, `-` или номера.
- Вложенные `<ul>` превращаются во вложенные списки только при наличии более одного содержательного `li`.
- Одиночный `<li>` с заголовком разворачивается в заголовок.

### 6.3. Инлайн-разметка

- `font-weight:bold` / `<b>` / `<strong>` → `**...**` в Markdown и `w:b` в DOCX.
- `font-style:italic` / `<i>` / `<em>` → `*...*` и `w:i`.
- `text-decoration:underline` → `<u>...</u>` в Markdown/PDF HTML и underline run в DOCX.
- Соседние фрагменты с одинаковыми атрибутами объединяются.
- Классы `fontN` не используются для определения семантики.

### 6.4. Таблицы

- Построить прямоугольную сетку, расширив `colspan`/`rowspan`.
- Первую строку считать шапкой, если все её ячейки Жирные.
- Markdown:
  - простая прямоугольная таблица без span → GFM pipe table;
  - сложная таблица → исходная HTML-таблица как fallback.
- DOCX/PDF — нативная таблица.
- Пустые ячейки сохраняются.
- Ячейки из одного символа помечаются предупреждением `suspicious_cell`.

### 6.5. Изображения и подписи

- Изображения копируются без перекодирования в `assets/`.
- Относительные пути сохраняются с кириллицей.
- Атрибут `style="width:440pt;height:276pt"` преобразуется в размеры PDF/DOCX.
- Подпись ищется среди соседних абзацев по регулярному выражению `Рисунок\s+\d+`.
- Подпись не перенумеровывается.
- Изображение без подписи и подпись без изображения фиксируются в отчёте.

## 7. Форматы вывода

### 7.1. Markdown

- Кодировка UTF-8, UNIX-переводы строк.
- Заголовки `#`, `##`, `###`.
- GFM-таблицы; HTML fallback для сложных таблиц.
- Изображения: `![alt](assets/имя.jpg)`.
- Подпись размещается сразу после изображения курсивом.

### 7.2. DOCX

- Нативные стили `Heading 1`…`Heading 3`, `Normal`, `Caption`.
- Нативные таблицы с видимыми границами.
- Изображения встраиваются, ширина ограничена printable area страницы.
- Формат страницы A4, поля 2 см, базовый шрифт Times New Roman 11 pt.
- Кириллица задаётся явно для `w:rFonts`.

### 7.3. PDF

- Промежуточный HTML создаётся из intermediate representation, а не из Markdown.
- Рендер: WeasyPrint.
- Формат страницы A4, поля 18–20 mm.
- Таблицы: `table-layout: fixed`, `break-inside: avoid`, повтор headers в `thead`.
- Изображения: `max-width: 100%`, сохранение пропорций.
- Поддержка разрывов страницы перед `<h1>` через опцию `page_break_before_h1`.

## 8. Интерфейсы

### 8.1. CLI

```bash
uv run html2doc convert ./лекции --to md,pdf,docx --out ./output
uv run html2doc convert ./лекции/лекция-1.htm --to md --out ./output
uv run html2doc gui
uv run html2doc web --host 127.0.0.1 --port 8000
```

Выход: список обработанных файлов, счётчик ошибок и предупреждений, ненулевой exit code при фатальных ошибках.

### 8.2. Qt6 GUI

- Выбор одного/нескольких файлов или каталога.
- Чекбоксы форматов.
- Выбор output directory.
- Дополнительные опции: page breaks before h1, копирование assets, уровень предупреждений.
- Кнопки `Конвертировать`, `Отмена`, `Открыть результат`.
- Progress bar и таблица логов с фильтрацией по уровню.
- Фоновая работа через `QThread`.

### 8.3. Web API

- `GET /` — форма загрузки ZIP.
- `POST /api/jobs` — multipart upload `.zip`, возвращает `job_id`.
- `GET /api/jobs/{job_id}` — статус и логи.
- `GET /api/jobs/{job_id}/result` — ZIP с каталогами результатов.
- Ограничения: только `.zip`, максимум 100 MB, не более 500 файлов, не более 2000 изображений.
- Защита от path traversal и symlink.
- Временные файлы удаляются через TTL.

## 9. Отчётность

`conversion-report.json` содержит:

```json
{
  "source": "лекция-1.htm",
  "formats": ["md", "pdf", "docx"],
  "warnings": [
    {
      "code": "orphan_caption",
      "severity": "warning",
      "message": "Подпись без изображения",
      "location": "p:78"
    }
  ],
  "stats": {
    "headings": 62,
    "tables": 6,
    "images": 6,
    "copied_assets": 6
  }
}
```

Коды предупреждений: `orphan_caption`, `image_without_caption`, `colspan_table`, `ragged_table`, `suspicious_cell`, `manual_marker`, `multiple_h1`, `missing_image`, `parse_error`.

## 11. Критерии приёмки

1. Все 13 файлов каталога `лекции` конвертируются без падений.
2. 58 изображений скопированы/встроены без потери.
3. Markdown содержит таблицы и изображения.
4. DOCX открывается и содержит нативные таблицы и изображения.
5. PDF содержит текст, таблицы и изображения, кириллица отображается корректно.

## 12. Ограничения

- Качество результата ограничено качеством OCR исходников: отсутствующий текст и повреждённые ячейки не восстанавливаются.
- Текст внутри растровых изображений не распознаётся.
- В GUI требуется графическое окружение; в headless-среде проверяется только импорт и логика.
- WeasyPrint требует системные библиотеки Pango/Cairo/HarfBuzz; в целевой среде они присутствуют.
